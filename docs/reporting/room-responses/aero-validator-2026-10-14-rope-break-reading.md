# Room response: the rope-break reading in section 4.1 (2026-10-14, aero-validator)

Rod read section 4.1 in the delivered copy and asked if the project
allows rope breaks, as in snapped ropes being acceptable. It does not.
This note records the reading check and one wording fix.

## The facts

- A break is an instant disqualification. DECISIONS [2026-08-14]: at the
  first step past 3.5 per cent line strain the line breaks, any_broken
  latches and the evaluator rejects the design. No wreckage path exists.

- The section 4.1 sentences describe the arming window of the detector,
  not permission. The relax run is a numerical settle. The rapid path
  injects starting velocities that over-strain healthy lines and trip
  the gate. Every healthy winner reads reject on the default path
  (NR-013).

- The 2026-08-14 rule from Rod: breaks only during real operation, so
  settle transients do not break healthy machines. The 2026-09-16 ruling
  narrows the check to the measurement window. Both speak to the
  instrument.

- The pending change removes false rejections. It adds no tolerance. The
  campaign ran the check across both phases, stricter than the ruling,
  and the winner passed that form. The winner reads no break on the
  window (the section 3.3 gate table), and the cold and ruling files
  hold no latch.

- The 09-16 ruling is not yet in the code. The draft says so, and the
  plate label reads "not yet in the code".

## The wording fix

The shorthand invites this exact alarm. Two forms to reword at the
author pass:

  Reads as permission. Candidate: "The evaluator arms the rope-break
  check across the relax and the window."

- "breaks only during real operation" reads the same way. Candidate:
  "the check judges only real operation".

The register row NR-025 carries the same shorthand ("rope breaks enabled
