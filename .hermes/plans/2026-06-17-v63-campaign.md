# V6.2 Dynamic Validation Plan — k_mppt Calibration Fix

> **Critical dashboard finding:** V6.2 design produces 393 kW (786% rated) with
> tether FoS=0.1 when run with the canonical k_mppt=614.9. This gain was
> calibrated for a 5-line 10 kW system — it cannot hold a 12-line rotor at its
> design TSR. The rotor runs away.

## Root cause

The MPPT law is: `τ_gen = k_mppt × ω²`

At equilibrium: `τ_aero(ω) = τ_gen(ω)`

The aerodynamic torque at design point:
```
τ_aero = ½ρπR³ × Cp(λ)/λ × v²
```
where λ = ωR/v = 4.1 (design TSR), Cp = Cp(4.1) from BEM.

For equilibrium at the design point:
```
k_mppt = ½ρπR⁵ × Cp(4.1) / 4.1³
```

**k_mppt ∝ R⁵.** The canonical value 614.9 was calibrated for R≈5m (5-line system).
At n=12, R≈10.6m, so correct k_mppt ≈ 614.9 × (10.6/5.0)⁵ ≈ 27,000.

The dashboard uses 614.9 regardless of geometry — so it applies 44× too little
generator torque. The rotor spins up to 82 rpm (2× design TSR), producing 8×
rated power through a structure sized for 1×.

## Hypothesis

**With correct k_mppt, the V6.2 design produces ~50 kW at ~40 rpm with FoS≥1.0.**
The static optimization is valid — only the controller gain needs to match the design.

## Phase 1: Verify hypothesis (tonight, ~30 min)


earlier plan. But this is unlikely — the MPPT controller is a standard torque-
following law that should hold any rotor at its design TSR if properly calibrated.
