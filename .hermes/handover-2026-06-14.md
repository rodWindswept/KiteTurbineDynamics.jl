## What happened this session

### Core model refactor: expansion blades = generating rotor blades, banked

The expansion rotor blades now use the **same annulus** as the generating rotor:
identical tip radius, hub radius, chord, and blade count — just banked downward
toward the next ring on the TRPT shaft.

| Field | Before (toy) | After (real) |
|-------|-------------|--------------|
| Blade span | 1.0 m independent | 5.0 m (from BEM rotor radius) |
| Blade chord | 6 cm independent | 56 cm (0.113 × rotor radius) |
| Hub radius | 0.15 m independent | 1.25 m (25% of tip radius, matching AeroDyn BEM) |
| n_blades | 3 hardcoded | from `p.n_blades` (5 or 8) |
| Bank angle | bridle_angle_deg 5-30° | bank_angle_deg 5-45° |

The mean aerodynamic radius now includes the ring position:
```
r_mean = r_nominal + (hub_radius + tip_radius)/2 × cos(bank)
```
instead of the previous `r_nominal + span/2 × cos(bank)` which treated the blade as
starting from the shaft center (no annulus).

### Search space reduced: 13-DoF → 11-DoF

Blade geometry is no longer free — only `n_expansion` and `bank_angle_deg` remain.
`TRPT_V6_DIM = 11`.

### Force-first structural model

`F_radial` from expansion rotors is injected directly into `_evaluate_trpt_design_impl`
as ring compression relief:
```
F_v = max(F_in_per_vertex_aero - F_centripetal - F_radial/n_lines, 0.0)
```
`r_eff` is still used for torsional collapse lever-arm calculation.

### Settle fix

`settle_to_operational_state` now computes the aerodynamic ω scan at the **design**
hub position (from `u0`) instead of the equilibrium hub position. This fixes ω_eq=0
when expansion rotors shift the structural equilibrium.

### Dashboard integration

- `--expansion <angle>` and `--n-expansion <N>` flags added to interactive dashboard

## Open items for next agent

### Immediate
1. **Fix ring element FEA for expansion rotors properly.** The current workaround
   (try-catch in `ring_element_analysis` + NaN guard in `capture_frame`) returns
   zero-utilisation frames when the FEA solver fails. Root cause: `rope_forces.jl`
   uses `sys.effective_radii` for attachment positions when expansion rotors are
   present, but `ring_element_analysis.jl` uses `node.radius` (nominal). This
   inconsistency produces unbalanced forces → singular stiffness matrices → LU

## Key physics to respect

1. **Expansion blades = generating rotor blades.** Same mould, same annulus
   (HubRad to TipRad), banked downward. Do NOT introduce independent blade sizing.
2. **Force-first structural model.** F_radial directly reduces ring compression.
   r_eff is for torsional collapse only. Do NOT revert to displacement-only.
3. **Ground ring is ground-supported.** Structurally irrelevant for airborne mass.
   NaN in ground-adjacent FEA is acceptable.
4. **Settle uses design hub position for ω scan.** Do NOT read wind at equilibrium hub.
5. **Bank angle is from rotation plane**, not from shaft axis. 0° = pure thrust,
   90° = pure radial (theoretical, blade would hit tethers).
